# LumiThink 2.0 产品需求文档（PRD）

> 版本：2.0.0-draft ｜ 日期：2026-10-12 ｜ 状态：讨论稿（非已交付功能清单）  
> 对应计划：[ROADMAP.md](./ROADMAP.md)  
> 优先级：P0 = 首个可用闭环必需；P1 = 后续重要；P2 = 远期探索。

## 1. 产品定位与变更缘由

**LumiThink 是面向儿童成长的循证、多模态、设备无关的个人 AI 陪伴与学习支持平台。**

它不是“数学作业诊断工具 + 语音外设”，也不是以延长陪聊时间为目标的聊天机器人。产品服务于儿童理解世界、学习、表达、探索、情绪调节和自主能力的长期发展。

旧版 README 中以数学思维诊断和认知分数为中心的定位、示例与完成状态，视为历史原型，不再作为 2.0 的产品承诺；旧页面和事件采集结构可以评估复用，但必须重新验收。

**北极星原则：让儿童逐渐更有能力独立完成自己想做的事，而不是越来越离不开 Lumi。**

**R1 第一天的专业能力要求：** Lumi 应能够运用受审查的儿童教育学与发展心理学知识，提供**日常情绪识别/调节支持**和**学习习惯/困难任务启动支持**。必须通过具体可验证的 Skill 与 Evidence Card 实现，而不只是写一句“你是儿童心理学专家”。这不构成心理诊断、心理治疗，也不保证仅通过 AI 对话即可改善情绪或习惯；效果要通过后续观察验证。

### 1.1 设计原则

1. **Child-first**：尊重儿童年龄、意愿、注意力与现实中的亲子/师生关系；不以留存时长、情感依赖为优化目标。
2. **Evidence-centered**：专业建议附适用条件、证据来源、限制；禁止把 AI 猜测包装成医学、心理或教育学结论。
3. **Memory with humility**：记住观察事实及来源，假设必须标明不确定性，允许纠正、撤回、过期和删除。
4. **Stable persona**：核心人格、安全边界稳定；表达风格可调，不随单轮对话“自我进化”。
5. **Multimodal and device-agnostic**：文字、语音、触屏、鼠标及可视化场景共享会话和儿童模型；核心不依赖 ESP32、XVF3800 或某一家模型。
6. **Human-governed evolution**：策略、人格、记忆规则的高影响变更必须经过评价和适当的监护人审核；系统不得自动改写自己的顶层规则。
7. **Privacy by design**：最小收集、默认不长期留存原始音频、凭据与儿童数据分离、可审计和可删除。
8. **Everything is a plugin（架构决策）**：主 Agent Runtime 选择 DeepSeek Harness（DSH）与 Cordis 插件组合；LumiThink 的领域规则、记忆、证据和客户端协议采用独立接口与可审计插件实现，而不是修改 DSH 上游核心。

## 2. 用户、角色与任务

| 角色 | 主要任务 | 权限与边界 |
| --- | --- | --- |
| 儿童用户（首期仅 1 名） | 自然对话、阅读探索、操作学习画布、表达困惑、纠正记忆 | 能知晓正在与 AI 互动，主动退出或拒绝建议；无法修改安全与模型密钥 |
| 监护人 | 授权、配置策略、查看必要的学习支持摘要、审阅候选敏感记忆、删除数据 | 不以“秘密监听/逐字监控”为默认产品模式；危险升级按透明规则处理 |
| 维护者（首期与监护人可能同一人） | 发布版本、维护 Evidence Cards、评估 Skill 与故障 | 使用独立管理权限，不得绕开儿童隐私默认规则 |
| 外部端（语音设备、Web/PWA） | 输入事件、展示场景、播放响应 | 仅有被授予的会话与能力权限，不直接访问 Child Memory |

真实姓名、出生日期、住址、学校和私人对话不得写入公开 Git 仓库、Issue、演示数据或测试报告；使用匿名标识与合成案例。

### 2.1 要解决的核心问题

- 面对困难知识点、阅读内容或复杂任务时，儿童需要适龄、渐进、可操作的支持，而不是直接获取答案。
- 儿童的兴趣、学习证据、有效引导方式随时间变化，单轮大模型缺乏可靠的连续性。
- 家长希望了解“如何更好地支持孩子”，而不是得到缺乏校准的心理评分或标签。
- 纯语音不能满足数学表征、阅读标注、排序和绘图等视觉活动。
- 固件、设备、模型供应商迭代不能迫使核心产品重写。

## 3. 产品体验与主要场景

### UC-01 具备循证引导能力的文字陪伴与探索（P0）

**路径：** 儿童进入 Web → 输入问题 → Harness 检索本轮必要上下文 → 输出友善、准确、适龄回应 → 儿童可继续追问、拒绝或纠错。

**验收：** 能跨轮保持一致人格与上下文；不知道时承认不确定；不制造 AI 与儿童的排他性关系；日常困扰能选择适龄且有证据边界的支持策略，不强制长时间对话。

### UC-02 阅读与理解支持（P1；首批专业 Skill 候选）

儿童阅读经授权的文本，能够点击生词、听朗读、复述和完成推断提问。优先理解与表达；少量问题用于探查理解，不形成未经验证的能力总分。遵守书籍内容授权与版权边界。

**验收：** 可从儿童的具体问题切换到相应阅读策略；能够指出所用原文段落；不会把一次正确或错误回答变成长期能力定论。

### UC-03 困难任务启动支持（P0；首发专业 Skill）

当儿童表达“不会做”“不想开始”等困难，Lumi 先区分任务难度、情绪与可用支持，提供可选择的最小下一步；允许求助可信成年人、休息或结束交互。

**验收：** 不羞辱、催逼、恐吓；不替代儿童完成应自主完成的作业；能够撤回或调整不适用策略。

### UC-04 交互式视觉场景（P1）

浏览器提供 Activity Canvas，包含操作对象、步骤反馈、可访问的替代控件与撤销。示例：数轴/十进制积木、词语标注、情节排序、简易思维画布。

**验收：** 拖动/动画在客户端即时完成，Agent 仅处理有语义的事件；所有场景均有版本化 schema、输入校验和允许的动作集合；不得执行模型生成的任意 JS/HTML。

### UC-05 语音交互（P1，硬件依赖外置）

经协议适配器连接任意合规客户端，如已有小智设备；语音消息与文本进入相同 Agent Session，回应可由设备播放。后续可以与浏览器画布协同。

**验收：** 更换设备固件无须修改 Core；能处理开始、取消、打断、断线重连；不在日志中默认保存儿童原始语音；未支持的设备能力明确降级。

### UC-06 家长支持界面（P0 基础能力，P1 扩展）

完成监护人授权、隐私配置、记忆查阅/更正/删除、孩子支持性活动摘要和候选策略审阅；避免默认查看私密逐字对话。

**验收：** 权限隔离有效；可解释每条持久化记忆来自何种来源；敏感项目写入有审查和操作记录。

### UC-07 日常情绪识别与调节支持（P0；首发专业 Skill）

儿童表达沮丧、生气、担心或失望时，Lumi 首先倾听并允许孩子自主描述体验；可通过年龄适宜的情绪词汇、情境澄清、自主选择应对方式和简短复盘提供支持。不要强迫积极、要求停止哭泣或将一次情绪视为心理健康疾病的证明。

**验收：** 在“情绪强烈/尚未说清原因/不愿继续谈/与家长发生矛盾/需要现实成年人支持”的合成场景中作出有区别的适宜回应；在严重危机线索下停止常规陪伴脚本，遵循安全升级路径；不独自诊断、治疗或承诺隐瞒。

## 5. Harness 行为契约

### 5.0 运行时基座决策（ADR-001）

- **已确定**：采用 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）作为主 Harness Runtime。核心设计原则是 Cordis **Everything is a Plugin**，尽可能复用官方 Agent Loop、Session、Prompt、模型 Adapter、受控 Tool Pipeline 和 SDK。
- **架构边界**：LumiThink 的 Persona、Evidence/Skill Registry、Child Memory、Safety Policy、场景命令及客户端协议属于项目领域能力；通过 SDK/自定义 Cordis 插件/受控服务与 DSH 集成。业务数据不可直接依赖 DSH 私有事件格式，避免上游升级造成数据绑定。
- **首选技术路径**：复用现有 Next.js/TypeScript 前端；TypeScript 作为首期 Core/插件语言。是否采用独立 Node API 进程或 Next.js API 与 DSH SDK 的组合，由 R0 容器和生命周期 PoC 确定；不引入非必要 Python 服务。
- **不直接使用官方默认 Profile**：单独构造/验证 `lumithink-child`，默认不得拥有 Shell、PTY、通用文件读写、外部任意网络、自动插件安装、未授权子 Agent、系统命令与管理员操作；所有工具通过正向白名单和服务端角色鉴权。
- **数据保护**：DSH 当前是 Developer Preview 且未经安全审计，官方默认 `session-log-deepseek` 可能上传会话日志，默认反馈遥测也可能包含会话前缀。儿童专用 Profile 必须禁用非必要日志/遥测上传，并对任何实际模型 API 外发独立审查；Session JSONL、Checkpoint/持久化及备份纳入删除策略。
- **版本治理**：监控 [GitHub Releases](https://github.com/deepseek-ai/deepseek-harness/releases) 中 RC 和正式版，生产固定经验收的精确版本及插件版本；升级采用隔离测试 → 兼容性审查 → 安全/隐私回归 → 人工审批 → 灰度/回退。详见 [ADR-001](./adr/0001-deepseek-harness.md) 与 [DSH_UPSTREAM.md](./DSH_UPSTREAM.md)。

### 5.1 请求流水线

每轮请求采用可观测、可中断的流水线：

1. **Input Gate**：鉴权、事件校验、安全识别、是否需要升级人工支持。
2. **Context Builder**：按照最小必要原则装配 System Policy、Persona、当前 Session、相关 Child Memory、证据与可用工具；明确上下文预算和来源。
3. **Orchestrator**：路由到普通对话、专业 Skill、场景工具；限制调用次数、时间与费用。
4. **Execution**：执行受许可的工具，不授予模型任意数据库写权限和任意系统命令权限。
5. **Output Gate**：输出结构化响应/场景命令，检查儿童安全、内容适龄性、权限及数据暴露。
6. **Recorder / Curator**：最小必要审计事件；长记忆写入以候选、校验、审批/规则化准入进行。

**可复现性：** 每次交互记录不含秘密的模型标识、系统规则版本、Persona/Skill/Evidence 版本、检索项目 ID、工具结果摘要、耗时、评估结果。模型随机性意味着无法保证逐字复现，但要能复查决策路径。

**安全分层：** 入口、工具前、输出后均实施约束；不能只依赖 System Prompt 或一次 LLM 自检。

## 6. Persona 人格需求

- **核心不变项**：友善、诚实、好奇、尊重自主、承认 AI 身份、不操纵情绪、不建立排他关系、不提供无条件保密承诺。
- **可调项**：语言难度、回答长度、幽默程度、提问密度、故事化程度、语音节奏；儿童可反馈和修改。
- **关系记忆**：仅记录有助于后续服务、且符合持久化规则的共同活动与偏好，不塑造“只有 Lumi 最理解你”等依恋话术。
- **版本治理**：Persona 变更经 Eval 套件回归和监护人审阅；不得由单轮对话自动重写系统 Persona。

## 7. Child Memory 与学习证据

### 7.1 数据类型

- **Identity / Preference**：经授权的基础资料与可撤销偏好。
- **Experience**：共同活动、阅读历史、已完成事件。
- **Observation**：可回溯的具体行为，带任务、时间、来源（儿童自述/家长报告/系统事件）。
- **Hypothesis**：对观察的非诊断性、可反驳解释；默认不得作为确定事实。
- **LearningEvidence**：在特定任务上的操作证据，不自动折算成“智力”“执行功能”等分数。
- **StrategyTrial / Revision**：某策略在什么条件下产生什么可观察变化，以及冲突、纠正、过期历史。

### 7.2 写入与检索规则

1. 原始会话事件与长期记忆分离；不能“所有说过的话 = 永久个人档案”。
2. 每条记忆含 subject_id、type、claim、source、observed_at、confidence/status、sensitivity、review_at、supersedes 等元数据。
3. 只有有用、合规且经准入规则认可的候选可持久化；高敏感或高影响推断必须人工审阅或拒绝。
4. 检索按当前任务相关性、来源可靠性、时效和儿童纠正历史排序；冲突时提示不确定性。
5. 提供查看、更正、禁用个性化、导出、删除及过期清理能力；操作审计与实际数据删除分开管理。
6. 禁止凭单轮聊天进行临床诊断、人格定性、永久能力打分。
7. **父母能进行必要安全监督，但孩子知道何类信息会被保存和分享；默认不是隐形监控系统。**

## 8. 循证专业能力与 Skill

**Evidence Card 最小字段：** source_url / citation、研究类型、目标年龄、研究对象与场景、效应/局限、证据等级、更新时间、适用/排除条件、人工审核状态。

**Skill 最小字段：** skill_id/version、goal、入口信号、适用与禁用条件、循证依据、分步策略、工具能力、儿童可选择的退出路径、记录的结果与评价指标。

**R1 必须交付两项专业 Skill：** `Emotion Regulation Support`（适龄情绪词汇、倾听、选择性调节建议；不做临床治疗）与 `Homework Initiation`（任务澄清、难点确认、最小启动步骤、支持撤除）。两者都必须绑定人工复核的 Evidence Card、适用条件和禁忌，并通过多轮测试。R3 再扩展 `Reading Coach` 与更深入的证据治理，而不是第一天上线通用聊天机器人。

首批证据起点：[EEF 社会与情绪学习指导](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/primary-sel) 与 [EEF 元认知和自我调节指导（2025 修订版）](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition)。这些证据主要研究学校/成人主导的教育实践，不得直接宣称 AI Agent 已被证明能实现同等干预效果。

专业定位是**一般教育与日常成长支持**，不是医学诊断、心理治疗、正式测评，也不代替教师、家长和现实人际关系。

**证据治理：** 收集/检索 → 提取 → 来源核验与分级 → 形成候选 Skill 修订 → 离线评估 → 人工批准 → 发布与回退。论文中的效果不自动等于“AI 对这个孩子有效”。

## 9. 多模态与界面规范

- 核心处理统一的 `InteractionEvent`，对外产生 `AgentResponse` / `SceneCommand`；硬件专属属性只能在 Adapter 边界层处理。
- Web/PWA 为第一公民入口：文本、触摸、鼠标、键盘；语音可独立存在。
- Agent 发出声明式 `SceneSpec`，由可信组件注册表渲染；不执行 Agent 生成的任意脚本。
- 点击/拖拽/动画由客户端本地处理，只有完成任务、请求提示等语义事件进入 Agent；支持撤销、键盘替代操作和明确反馈。
- 初期使用普通 HTML/React/SVG；高密度 2D 互动有充分需求后再引入 PixiJS；大型 3D 游戏不是核心需求。
- 第二设备接入需明确会话归属、权限、播放冲突、打断与离线回退。

## 10. 安全、隐私和非功能需求

### 10.1 不可妥协的产品安全要求

- 对未成年人明确标识为 AI；禁止鼓励排他、依赖、长时间黏附、情感操控和“不要告诉家长”等互动。
- 遇到自伤、虐待、严重危险或其他紧急风险信号时，采用适龄、非诊断性支持，推动联系可信成年人及适当的本地求助渠道；不承诺 AI 可独自处理危机。
- 角色、系统提示、证据卡、工具输出都视为可被攻击的输入；受信任策略与访问控制不能由普通内容覆盖。
- 存在儿童数据时采用独立的隐私规则、监护人授权和透明说明；对第三方模型供应商的数据用途、地域、保留和日志行为进行评估。

### 10.2 初期工程指标（候选，需在 R1 建基线）

| 项目 | 候选要求 |
| --- | --- |
| 安全 | 高严重度测试场景全部通过；未通过不发布 |
| 可靠性 | 错误可归因，有超时和可理解的失败提示 |
| 可观测性 | 记录请求 ID、版本、耗时、费用；不记录密钥或默认全量儿童正文 |
| 响应体验 | 优先流式首字、可中止；P50/P95 通过真实部署测量后定目标 |
| 数据安全 | TLS、服务端鉴权、角色权限、加密备份、测试恢复与删除 |
| 成本 | 每会话 Token/API 成本可计算，可设置每日预算和熔断 |
| 可移植性 | 一台 Linux 服务器可部署，容器化和数据库迁移有回退方案 |

### 10.3 法规与参考

## 11. 指标与评估

**北极星结果：** 在可观察的具体任务中，儿童能更独立地开始、思考、表达与完成，而不是增加 AI 使用时长。

- **体验指标**：儿童可拒绝/更改引导、反馈“有帮助/没帮助”、被打断或超时后的恢复质量。
- **学习过程**：在任务上下文中观察独立开始、提示次数、解释质量、迁移尝试（不把单次结果当长期能力）。
- **可信性**：有据可查的专业建议占比、记忆引用正确率、错误记忆纠正成功率。
- **工程指标**：回归通过率、关键安全场景覆盖率、可用性、P95 时延与每轮成本。
- **反指标**：排他性关系话术、错误贴标签、意外敏感信息外泄、隐形监控、强迫留存或过度使用。

初期为单儿童、N-of-1 观察，不把前后变化当作严格的因果证明；尽可能结合儿童主动反馈、家长观察和真实任务结果。

## 12. 发布范围与明确非目标

### 2.0 首个可用闭环（具体场景待下轮确认）

必须完成：文本会话、基本 Persona、输入/工具/输出安全、Model Gateway、版本日志、基础评测、监护人最小控制与数据删除流程；**第一天即包含两个受循证约束的专业 Skill（Emotion Regulation Support + Homework Initiation）及其最小 Evidence Cards**。长期记忆实现受控偏好/确认事实的示范闭环及纠错删除；R2 再启用复杂的记忆提议、观察/假设分层。

不必首版完成：4 麦硬件、固件 OTA、IoT 平台、复杂游戏世界、自主微调、大规模向量库、连续心理评分、数十种 Skill、商业化、多用户运营。

### 最小产品验收（DoD）

1. 情绪支持和困难作业启动两个专业场景都能完成多轮交互，分别可追溯 Evidence Card 与 Skill 版本；保持人格和安全边界。
2. Mock 模型和真实模型共用相同 Core API；不依赖语音设备上线。
3. 可运行安全回归集，严重失误阻断发布；可追溯版本、工具和策略。
4. 儿童数据能被最小化管理、可查询/更正/导出/删除，且不写到公开代码或默认日志。
5. 每次上线有可复用测试报告、迁移/回滚步骤和明确限制。
