## 1. 目标与边界

本策略回答四个问题：**系统存什么、存多久、谁能看到、怎么删**。它适用于当前 Web MVP（单家庭、单进程、进程内内存态）中的全部数据种类。R1-09 的验收基线：

- **默认最小化采集**：记录开关（`conversation_recording`）默认关闭——不保存聊天正文、不存音频、无需时不存完整聊天（issue #21 交付范围 2）。
- **删除即真删除**：删除覆盖领域记忆、会话历史、临时工件（轮次事件缓冲）与 DSH 会话映射；删除后的跨 Session 检索为 0（issue #21 AC 1）。
- **操作与数据分离**：审计与删除台账只含结构化事实（id + 计数），**结构上没有承载被删除正文的字段**（issue #21 交付范围 4）。
- **外发诚实**：撤销授权后不再向供应商发起新请求（R1-06 传输前门禁）；供应商侧删除承诺不可虚构（issue #21 AC 3）。

## 2. 数据分类与保留矩阵

> 本表为 `lib/domain/lifecycle/policy.ts` `DATA_KIND_POLICIES` 的镜像。矩阵的机器可校验约束：每个 `carriesChildText=true` 的种类必须有具体删除路径。

| 数据种类 | 可含儿童正文 | 存储位置 | 保留规则 | 删除路径 |
| --- | --- | --- | --- | --- |
| `conversation_history` 会话历史 | 是 | 进程内存 | 记录开关开启时：每会话最近 40 条；关闭时不保留正文 | 主体级清除（lifecycle erase 硬删除） |
| `turn_stream_events` 轮次事件缓冲（临时工件） | 是 | 进程内存 | 轮次进行中必需；记录开关关闭时终态即清，开启时随进程生命周期 | 主体级清除（含在途轮次取消） |
| `dsh_session_mapping` DSH 会话映射 | 否 | 进程内存 | 会话生命周期；仅映射 id 与状态，无正文 | 主体级清除（映射关闭） |
| `memory_entries` 领域记忆 | 是 | 进程内存 | 候选/确认事实按记忆域规则（过期、复核、谱系） | 主体级清除 + memory.delete（谱系硬删除） |
| `memory_audit` 记忆审计环 | 否 | 进程内存 | 有界环 256 条；仅结构化事实（结构上无正文字段） | `purgeAudit` 独立清理 |
| `guardian_audit` 监护人安全审计环 | 否 | 进程内存 | 有界环 500 条；仅结构化事实（结构上无正文字段） | 随进程生命周期（#18 设计） |
| `runtime_trace` 运行时 Trace | 否 | 进程内存 | value-free：仅规则/计数/id，无正文（#15 设计） | 随进程生命周期 |
| `gateway_audit` 网关审计 | 否 | 进程内存 | value-free：供应商/预算/结果码，无正文（#14 设计） | 随进程生命周期 |
| `deletion_ledger` 删除台账 | 否 | 进程内存 | 有界台账 100 条 tombstone；仅 id 与计数 | 随进程生命周期（跨进程恢复需持久化台账——TECH_STACK §3 待定项） |
| `idempotency_ledger` 幂等台账 | 否 | 进程内存 | 有界台账 500 条；键 (verifiedActor, requestId) → 结构化 ack 引用 + 载荷 64-bit FNV-1a 摘要（无正文，#21 评审 P0-1 修复） | 随进程生命周期（内容无关，同 runtime_trace） |
| `audio` 音频 | 否 | 无 | **不采集、不存储**（当前部署没有语音路径；R5 规则：不默认保存原始录音） | 不适用（无存储） |
| `vendor_side` 供应商侧数据 | 是 | 供应商侧 | 仅当第三方外发开启时产生；保留期限以供应商评审结论为准（待核实） | **不可由本系统担保**——撤销授权后不再发起新请求；供应商侧删除承诺不可虚构 |

## 3. 记录开关（conversation_recording）

- **默认关闭（最小化采集）**。关闭时：轮次照常执行，但用户输入与模型输出**都不写入会话历史**（下一轮无上下文延续——为最小化付出的诚实代价，监护人可在保存说明中看到）；已结束轮次的事件缓冲在终态立即清除（缓冲含儿童正文，属临时工件）；SSE 迟到订阅者与外部 trace 同样得到不可区分的"不可用"应答。
- **开启**：每会话保留最近 40 条对话文本（进程内存，重启即清），用于会话内上下文延续；已结束轮次缓冲保留至进程生命周期结束或显式清除。
- **开启需要当前告知版本已确认**（与所有"使能"开关一致）；关闭是安全方向，永远允许。
- 监护人可见保存说明：告知文档 v1.1.0 `data_lifecycle_saving` 一节（`lib/domain/guardian/authorizations.ts` 注册表）+ `/parent` 控制台"数据生命周期"区。

## 4. 删除策略（覆盖范围与语义）

主体级清除（`POST /api/v1/guardian/data/erase`，action `erase_child_data`，仅监护人）一次覆盖：

1. **领域记忆**：逐条走记忆域自身鉴权删除路径（含 `supersedes` 谱系硬删除）；检索同源同存，删除后跨 Session 检索为 0（无独立缓存可孤儿化）。
2. **会话历史**：该儿童全部会话记录与历史正文删除。
3. **临时工件**：全部在途轮次先取消（`turn.cancelled` 如实标注 `by: system`，输出永不触达儿童），已结束轮次的事件缓冲删除。
4. **DSH 运行会话**：被删会话的映射关闭（终态），被删会话 id 无法恢复进入旧 DSH 会话。
5. **删除台账**：写入一条结构化 tombstone（id、时间、主体、操作者角色、各类计数）。

**备份保留边界（R1-08 更新，诚实披露）**：R1-08（issue #20）引入**加密运行时快照**作为备份（AES-256-GCM，`lib/server/snapshot/`；选定事实源 = 进程内组合态，prisma schema 仍零差异，见 ADR-0006 §2.5）。快照**包含**删除台账（seq 连续性随快照跨进程携带），**排除**活跃 Bearer 会话、锁定计数、观测用审计环与 DSH 会话映射。恢复语义：

- 恢复**当前**快照文件：已确认事件不丢（删除先于快照 ⇒ 内容已清 + 墓碑已在）。
- 恢复**旧档**（`deploy/restore.sh` 路径）：自动置 `LUMITHINK_SNAPSHOT_RESTORE_REPLAY=1`，启动恢复后**立即执行删除重放**（`action: "replay_child_deletions"`）：重放按台账重新清除该主体当前存在的一切数据（issue #21 AC 2"备份恢复后的删除重放"，R1-08 快照级自动化验收）。
- 台账本体仍为进程内存；其**副本**现随加密快照持久化（0600、归档轮转见 deploy/runbook.md §5）。完整 SQLite/WAL 级持久化仍列入 TECH_STACK §3 数据建模任务的决策项；确认变更与快照原子写之间的毫秒级窗口如实披露（ADR-0006 §2.5）。

## 5. 查看与导出（按授权身份）

| 面 | 路由 | 角色 | 内容 |
| --- | --- | --- | --- |
| 数据清单 | `GET /api/v1/guardian/data` | guardian + admin（只读） | 计数与 id（会话数、保留正文条数、记忆条目分状态、轮次缓冲、DSH 映射、台账记录数、记录开关态）——**无正文** |
| 导出已保存内容 | `GET /api/v1/guardian/data/export` | **仅 guardian** | 会话历史正文 + 完整记忆条目 + 诚实排除清单（value-free 审计不导出、供应商侧数据不可导出、音频不存在） |
| 删除 / 重放 | `POST /api/v1/guardian/data/erase` | **仅 guardian** | 结构化结果（各类清除计数 + tombstone id）；被删正文无法返回（已不存在） |

儿童本人（`chd_demo_001`）经记忆域既有路径（确认/更正/删除本人条目）行使个体数据权；主体级导出/删除是家庭监护人职责（PRD §7.2 规则 5：操作审计与实际数据删除分开管理——审计事实在监护人审计环，数据删除在数据本体）。

## 6. 外发与供应商（不可虚构保障）

- `third_party_data_egress` 关闭（默认）时，第三方类供应商的调用在**任何传输前**被网关拒绝（GATEWAY_NO_PROVIDER），供应商请求数为 0。
- 撤销家庭 consent 或关闭外发开关后，**本系统不再向供应商发起新请求**（已在 #18 传输前门禁 + #21 复核）。
- **已外发到供应商侧的数据，本系统不能担保其删除**：供应商的保留期限、地域与日志行为必须在其启用前逐一完成独立数据外发评审；未核实的事实一律以"待核实"呈现（告知文档 pendingVerification 标记）。任何声称"供应商已删除"而无评审结论的表述都是虚构，禁止出现。

## 7. 新数据种类准入（AC 3）

新数据种类进入系统前必须：

1. 在 `lib/domain/lifecycle/policy.ts` `DATA_KIND_POLICIES` 增加一行（标注是否可含正文、存储位置、保留规则、删除路径）；
2. 在 [PRIVACY_DATA_FLOW.md](./PRIVACY_DATA_FLOW.md) 矩阵增加对应行与数据流说明；
3. 通过保留矩阵完整性测试（正文类种类必须有删除路径；测试强制）；
4. 随 PR 审查（独立 Review Agent），披露于 PR body。
