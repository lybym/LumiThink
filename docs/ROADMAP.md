**2026-10-25 正式基线：设计评审通过（Design GO）。P0/P1 获准开展，协议互通、真实取消、设备验收和部署切换仍受各阶段 Gate 约束。** 当前优先级以本路线图和 [P0/P1 清单](P0_P1_PLAN.md) 为准；旧 R0/R1/E2E 编号保留为证据，不再表示新阶段执行顺序。

| --- | --- | --- |
| P0 基线冻结 | 仓库、运行目录补丁、PR #76、设备与版本矩阵、隔离验证环境、回滚配置 | 形成可复现基线，已知故障有处置，Gate 记录通过 |

## 执行顺序

P0-01 → P0-02 / P0-03 → P0-04 Gate → P1-01 → P1-02 → P1-03 → P1-04 → P1-05 → P1-06 → P1-07 → P1-08 → P1-09 → P1-10 Gate。

这是保守串行顺序；任务清单提供可并行依赖。声纹实验、插件调研可提前做，但不能提前切换现有 UDS，也不阻塞 P1 官方客户端核心验证。P2/P3/P4 均需各自验收，不把风险集中到 P5。

## 验收规则

每项报告给出 commit、工具链、配置、数据来源、执行命令、结果与局限。合成模型可验证真实 DSH 进程机制，但真实供应商、音频、设备和人工评审必须单独标明。设计通过、自动化通过、实机通过和发布批准分别记录。当前候选 1.0.0-rc.1 与旧发布注册表保留；未来需要随实际实现重新生成证据，不能通过修改文档将旧证据升级为 A2A 验收。
