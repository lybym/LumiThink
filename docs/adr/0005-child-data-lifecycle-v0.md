# ADR-0005: Child Data Lifecycle v0 — 默认最小采集、记录开关与主体级删除

- 状态：Accepted（随 R1-09 / issue #21 交付 v0）
- 日期：2026-10-14
- 关联：[PRD FR-006 / FR-008 / §7.2](../PRD.md) · [Roadmap R1-09](../ROADMAP.md) · [MEMORY_POLICY](../MEMORY_POLICY.md) · [PRIVACY_DATA_FLOW](../PRIVACY_DATA_FLOW.md) · [ADR-0003](./0003-guardian-auth-v0.md)（监护人面）· [ADR-0004](./0004-child-memory-v0.md)（记忆域，跨存储删除传播归属本 ADR）· [TECH_STACK §3](../TECH_STACK.md)

## 1. 背景

R1-09 要求数据生命周期最小实现：记录开关、查看、清除和审计（Roadmap R1-09：删除测试通过、默认最小化）。此前已交付的存储面各管一段：#17 交互状态（会话历史 + 轮次事件缓冲）、#18 监护人会话/授权/审计、#26 记忆域（谱系硬删除仅覆盖记忆库自身，跨存储删除传播按 ADR-0004 §3 明确归属 R1-09）。缺一个跨存储的主体级生命周期语义，以及"默认存不存聊天正文"的决策。

## 2. 决策

### 2.1 记录开关默认关闭（默认最小化采集）

新增监护人功能开关 `conversation_recording`，**默认关闭**。关闭时轮次照常执行，但用户/模型正文都不写入会话历史（下一轮无上下文延续——诚实代价，写入保存说明），已结束轮次的事件缓冲（临时工件，含儿童正文）终态即清。开启需当前告知版本已确认。无论开关状态，音频不采集不存储（当前部署无语音路径）。不选"默认开启 + 可关闭"的原因：PRD §7.2 规则 7（默认不是隐形监控）与 Roadmap R1-09 验收"默认最小化"；正文留存必须是显式、可见、可逆的监护人选择。

### 2.2 主体级硬删除跨存储传播

`erase_child_data` 一次覆盖：会话历史、轮次事件缓冲（先取消在途轮次，输出永不触达儿童）、记忆域逐条谱系硬删除（复用记忆域自身鉴权删除路径，不旁路）、DSH 会话映射关闭。检索与存储同源，删除后跨 Session 检索为 0（无独立缓存面）。主体固定为服务端家庭注册表的 `chd_demo_001`，**永不是请求体字段**——载荷无法把清除重定向到别的孩子。

### 2.3 删除台账 + 恢复后重放（备份保留边界）

当前部署无离线备份（全进程内存，TECH_STACK §3）。为备份引入之日准备可证明策略：每次 erase/replay 写入一条**内容无关** tombstone（id/时间/主体/操作者/各类计数，有界 100 条）；`replay_child_deletions` 按台账对主体当前存在的数据再执行一次全量清除（备份恢复后重删，AC 2）。**如实边界**：台账为进程内存，跨进程恢复到新进程时台账不随行——持久化台账列入数据建模决策项；在该决策前本边界无实际暴露面。

### 2.4 查看面分级（最小内容暴露）

- 数据清单（guardian + admin）：计数与 id，**无正文**——管理员"只读监督"扩展为可见结构面但永远看不到正文。
- 导出（**仅 guardian**）：已保存正文（会话历史 + 完整记忆条目）+ 诚实排除清单。正文离开系统边界是家庭决定，独立管理员不参与。
- 删除/重放（**仅 guardian**）：结构化结果；被删正文无法返回。

### 2.5 审计分离（承 #26 纪律，扩展到生命周期）

操作事实进监护人审计环（新 kind：`data_view` / `data_export` / `data_erase` / `data_erase_replay`，target=childRef，detail=有界计数）；删除台账是独立结构。两者**结构上都没有**承载被删除正文的字段（emit 校验拒绝未知字段，测试强制"被删 claim 不出现在任何审计/台账序列化"）。另修复两个承自 #26 评审的生命周期相邻缺陷：correctMemory 两步写入改为先准入后落存（原子性，#26 P2-1）；未授权 `expirePastCandidates` 从静默 no-op 变为可观测 rejected 审计事实（#26 P2-4）。

### 2.6 告知文档 v1.1.0

产品语义变化（家长面从"无正文"到"显式开启后可查看/导出/删除正文"）走版本化告知注册表：新增 `data_lifecycle_saving`（保存说明）并改写 `monitoring_boundary`（1.0.0 的"逐字聊天内容不属于本版本的家长面"在 1.1.0 下不再成立）。1.0.0 保留注册供历史确认审计。

## 3. 与其他约束的关系

- **ADR-0004 不变**：记忆域候选→确认→检索→更正→删除语义零改动；本 ADR 只是从外组合其删除路径（含 2.5 的两处评审修复）。
- **R1-06 门禁不变**：consent 撤销拒绝新轮次、外发开关传输前拒绝（供应商请求数 0）继续成立；本 ADR 不新增任何供应商路径。
- **零 prisma 差异保持**：全部生命周期状态为进程内存，schema.prisma 零改动（无迁移/迁移测试要求）；持久化引入时按 TECH_STACK §3 决策并复审 MEMORY_POLICY/PRIVACY_DATA_FLOW 矩阵。
- **R1-06 遗留范围注记维持**：带会话的监护人 HTTP 取消入口（API_CONTRACT §12.3 "R1-09+"）**未被本 Issue 吸收**——issue #21 交付范围无取消项，该注记保持原样留给后续 Issue。

## 4. 后果

- 正面：默认状态不存儿童正文；一次操作即可把一个孩子的可恢复数据清到 0；删除/导出/重放都有自动化验收；审计永远只是结构事实；新数据种类有强制准入闸（矩阵 + 测试 + 审查）。
- 代价/限制：记录关闭时多轮对话无上下文（有意为之，已写入保存说明）；记录开启时已结束轮次缓冲随进程生命周期保留（有界、可随时清除）；删除台账/授权状态不跨进程；供应商侧删除不可担保（只能保证不再请求）；全部为进程内存，重启即复位（与 #17/#18/#26 同纪律，TECH_STACK §3 待定）。
