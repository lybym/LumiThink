## 任务范围与验收

### P0-01 核对仓库、部署补丁与设备现状，冻结源码清单

逐项核对 main、开放 PR #76、现有工作目录改动、WSLc 运行目录和小智覆盖文件；追溯 10 月 24 日 TTS、hello 与 Worker 补丁，记录采纳/另开修复/保留分支的决定。记录设备固件、运行 Profile、供应商与数据路径的脱敏摘要。

复用与边界：复用 #51–#58 的既有实现与验收记录；#58 的硬件记录仅作输入。不要混入未审阅改动，也不要把测试 Profile 当正式学习业务。

验收：

- 输出 commit / 补丁文件哈希 / 运行配置来源 / 已知偏差的矩阵；不提交密钥、原始日志或儿童资料。
- 每项运行补丁有去向及负责人；影响复现的未解决偏差阻断 P0 Gate。
- 复核 hello 异常与当前可用状态，区分历史跑通、当次冒烟和正式实机验收。
- 记录 PR #76 的审阅与合并/延期决定，不因本任务自动视为已批准。

### P0-02 锁定 A2A、SDK 与 DSH 兼容矩阵及协议 Fixtures

固定 A2A v1.0.1、协议头 1.0、官方 JS/Python SDK 精确版本、Node/Python/DSH 版本及候选插件提交；用隔离样例验证选定绑定、事件结构和取消语义，记录不兼容点。

复用与边界：以 docs/fixtures/a2a-v1.0 为输入；内部 DSH 沿用既有锁定版本。候选 dsh-a2a 的 Abort 不传播、内存 context 和凭据存储需要记录，正式插件接入在 P2。

验收：

- 提供可复现版本/包完整性/来源矩阵，包声称兼容不能代替实际编解码结果。
- 官方 SDK 解析并重编码 Task、Artifact 事件及 metadata；append/lastChunk 不出现在 Artifact。
- 明确 JSON-RPC 请求/响应与 SSE 外壳、标准错误和重复 CancelTask 行为；保存无敏感内容的 Fixtures。
- 验证 header 1.0、终态订阅错误、Task-only 应用策略与 SDK Store/handler 的适配风险。

### P0-03 建立隔离验证环境和可复现部署、备份与回滚基线

给 A2A 验证服务准备独立配置、端口、数据卷、受限账户与启动说明；旧 UDS 链路保持原配置。核对加密备份、当前删除/撤权台账保管位置、恢复顺序和资源预算。

复用与边界：复用既有部署、模型出口及加密快照工具，不另造供应商服务。这里只验证现有基线的可复现性及新环境隔离，不声称 A2A 已可运行。

验收：

- 从冻结清单在隔离目录重建现有基线并留脱敏启动/停止证据；主运行目录不受影响。
- 回滚步骤、备份范围、版本配置及校验值齐备，并完成隔离恢复演练。
- 记录有限 Worker、队列、模型并发、超时、内存和日预算初值；缺值不能默认为无限。
- 明确删除/撤权台账独立于可回退快照，恢复开放前执行清理；凭据不进入镜像/仓库。

### P0-04 P0 基线验收 Gate 与 P1 开发入口冻结

汇总源码、运行补丁、兼容矩阵、隔离环境、资源参数和回滚记录，形成可重放 P0 验收索引。

复用与边界：复核既有 100 次竞态证据与测试命令，明确可复用部分和 P1 新增项。

验收：

- 前三项交付逐项可定位 commit、命令、结果与局限，无关键复现阻断项。
- 明确锁定版本和实际运行目录一致；如不一致，列出隔离验证可接受范围且不能假称当前生产基线相同。
- 给出明确 GO/NO-GO、未关闭风险及处理任务；禁止以文档评审替代该 Gate。
- GO 仅开启 P1 核心验证，不批准切换现有 UDS、正式儿童数据或发布。

### P1-01 单 Agent A2A Server 与官方独立客户端协议骨架

用官方 JS SDK 建独立服务入口、Agent Card、JSON-RPC HTTPS/SSE、错误映射与 Task-only 业务适配接口；复用冻结 Fixtures。初期可用明确标注的合成执行器验证传输。

复用与边界：保留已有内部 Web/Runtime 合同；不建设 OpenAI-compatible 入口，不拆 Companion/Learning 两个 Agent。

验收：

- 官方独立 JS/Python 客户端发现 Agent Card、发送/流式、GetTask、CancelTask、订阅的基本协议往返通过。
- 所有成功受理业务关联 Task，参数/认证失败可标准错误；Skill 声明不作为授权依据。
- SSE 断开不默认取消；终态订阅按标准返回，客户端 GetTask 恢复。
- 明确 SDK handler/Task Store 接入 Task Manager 的边界，合成通过不标记真实 DSH Gate 通过。

### P1-02 SQLite 统一仓储、Task Manager 状态机与事务 Outbox

实现 Task / Conversation / Turn / Execution / Request Ledger / Outbox schema、迁移、状态版本条件更新及统一仓储；Task Manager 唯一写入公开状态和结果。

复用与边界：旧 Prisma schema 保持冻结；SDK Store 必须桥接同一仓储事务，不能与 SDK 默认 Store 双写。

验收：

- Task 可关联多个顺序 Turn，Execution 与 epoch/租约可追溯；标准状态和终态不可逆有约束。
- 输入受理、任务状态/结果与 Outbox 在对应事务中原子提交；任何失败点无半写。
- 并发状态版本竞争只允许一个合法提交，迟到回调不能改终态或追加正文。
- 数据库迁移/回滚风险有说明；不在数据库写事务内等待模型/网络，验证写锁竞争。

### P1-03 家庭租户、Client/Principal 双层认证与集中授权

实现最小家庭成员、关系、客户端注册和受限凭据；可信身份解析、授权范围、期限、撤销及会话绑定。为 DSH、飞书、设备授权预留同一可信入口，P1 用合成身份验证。

复用与边界：复用已有监护人认证和领域守卫；不建设完整用户管理平台。声纹识别与渠道 OAuth/机器人上线不在本任务。

验收：

- Client 和 Principal 分离；消息内 userId/householdId/role、A2A tenant/contextId 不能伪造授权。
- 跨家庭、跨用户 Task/Get/Cancel/Subscribe 和会话续接拒绝；同家庭共享事实按关系与操作决定。
- 撤权对已有流、缓存、工具提交与旧上下文及时生效；记录最小审计信息。
- 设备仅认证家庭，候选声纹不提升私有数据权限；短期授权范围/过期/撤销有负例。

### P1-04 持久幂等受理、首响应丢失恢复与执行派发租约

将作用域化 messageId、版本化请求指纹、Task 映射、取消意图及派发租约纳入事务；尽早发布 taskId，重复原消息恢复原任务，不重复推理。

复用与边界：保留现有 epoch 防串轮机制；原进程内去重不能满足跨重启和丢失首响应需求。

验收：

- 并发同 messageId 同请求只有一个 Task/有效执行；同键不同内容明确拒绝且不泄漏其他主体。
- 首响应丢失后重发原消息取得相同 taskId；取消意图先本地持久化，补发远端取消可测。
- 派发前复查权限/取消/限额；事务提交与 Worker 启动之间故障不盲目重试副作用。
- 24h 重试/7d 结果/至少30d最小墓碑为可配置初值；清理或重放不复活已删正文。

### P1-05 Task Manager 接入真实 DSH Worker 与 Runtime 租约

复用内部 Runtime Bridge，将真实 DSH 执行、Turn/Execution/epoch、Worker 注册、超时与退出证据接到 Task Manager；区分外部工作 DSH 与内部执行进程。

复用与边界：复用 #52、#53、现有 Profile、受限工具及模型出口。模型可采用合成供应商验证进程机制，需明确真实模型另验。

验收：

- 官方 A2A 请求可经真实 DSH 子进程产生准入结果；不能仅依赖 fake worker。
- Worker 归属/租约/会话映射可核对；崩溃、启动失败、失联各有真实状态及清理路径。
- 执行结果与公开 Task 结算分离，迟到结果受 epoch/状态版本约束。
- Task/Execution 关联的最小诊断能排障，不落儿童正文、工作资料或凭据。

### P1-06 安全准入、追加 Artifact、事件 Outbox 与快照恢复

将安全准入后的正文持久化为稳定 Artifact，逐片段事件带 ID/字节范围/摘要；区分状态、结构化数据、工具日志和可播正文。

复用与边界：复用既有输出 Gate 与短句准入；协议字段遵循 docs/fixtures/a2a-v1.0，摘要只用于完整性。

验收：

- append/lastChunk 在事件，片段 metadata 在事件，Artifact metadata 仅稳定属性；Outbox 可重放而快照聚合正文。
- 重复事件保持同 ID；同 ID 不同内容拒绝，合法重复词句保留；替换已公开前缀被拒绝。
- 快照与增量接合无缺口，SSE 重连不重新执行；终态用 GetTask，不能假设标准保证历史游标。
- 撤权/删除后停止事件交付；没有可靠水位时适配器不得自动从头补播。

### P1-07 真实取消、完成竞态及取消后不完整答案语义

实现持久取消意图、输出 fencing、协作停止/限期强停/隔离、真实执行结算；将标准 CancelTask 行为与本地 Abort 区分。

复用与边界：保留现有100次竞态基线，增加 A2A 与 SQLite 故障场景；DSH 插件 Abort 传播在 P2 单独验收。

验收：

- 覆盖取消先于派发、领取租约中、首响应丢失、完成竞争、重复取消、非协作 Worker；实际停止有证据。
- 仅收到取消命令或 whenIdle 不直接认定停止；限期未停止不能假成功，终态不可被迟到回调覆盖。
- 真实完成但正文被抑制时 COMPLETED + Task metadata outputSuppressedAfterCancel=true/answerComplete=false，客户端明确部分结果且不补播。
- 重复取消、已完成、已取消、已清理的返回通过锁定官方客户端的标准成功/错误 Fixture 验证；不自创状态或错误码。

### P1-08 重启恢复、数据删除优先与最小幂等墓碑

实现启动扫描、执行租约核对、取消恢复、Outbox 重放，以及删除/处理授权撤回跨 Task/上下文/缓存的清理契约。

复用与边界：复用既有数据生命周期与加密备份设计，P5 #61 完成真实部署备份恢复演练；本项必须提供模块级故障证据。

验收：

- 在事务提交、执行登记、Worker 启动、结果提交、Outbox 发布各切点重启，不重复执行未知副作用。
- 删除优先于7天结果留存：输入、Artifact、含正文 Outbox、缓存/待发及旧上下文均清理。
- 仅留必要受限墓碑及版本化 HMAC，不留正文或无密钥短句摘要；重试返回已清理/受限结果，不再执行。
- 撤销访问立即生效；处理授权撤回按范围删除；恢复旧快照前重放独立删除/撤权台账，测试已删数据不能复活。

### P1-09 有限资源、隔离、背压与内容最小化可观测性

落实冻结的 Worker/模型并发、家庭/全局队列、等待和执行时限、调用/token/日预算与内存上限；查询和取消保留处理容量，SQLite 避免网络长事务。

复用与边界：复用既有模型网关限额与日志基础；按整体方案 §13 初值测量后记录调整，不承诺未测吞吐。

验收：

- 容量满载时新任务明确拒绝/排队，取消与查询仍在有界期限处理，家庭间不无限饥饿。
- 超时、断连、非协作 Worker 和模型失败不泄漏进程/租约/队列槽。
- 记录 Task/Turn/Execution/epoch/版本/耗时与错误，不记录私人正文或凭据。
- 负载报告包括 SQLite 写锁/Outbox积压/Worker内存和限额实测，敏感日志扫描通过。

### P1-10 P1 官方双 SDK × SQLite × 真实 DSH 核心验收 Gate

建立独立官方 JS/Python 客户端的核心协议与应用契约验收，统一报告真实 Worker、持久仓储、身份隔离、流式与取消等结果。

复用与边界：复用既有 CI/领域门禁，增加必要 A2A 检查；不以候选 dsh-a2a 自测代替官方独立客户端。

验收：

- Task 创建/多 Turn/查询/流式/终态订阅错误/显式取消/重复取消/首响应丢失/并发幂等/跨主体拒绝全部通过。
- 真实 Worker 停止、取消完成竞争、快照增量、重启无重复执行、删除/撤权和满载控制测试关键路径零 SKIP。
- 第二轮 REVIEW2-01/02/03 各有测试证据，明确 P5 真实备份演练仍待完成。
- 提交版本/配置/命令/报告索引和 GO/NO-GO；仅为进入后续渠道验证依据，不批准生产切线、真实儿童资料或发布。

## 完成定义

每项保留实现 commit、测试命令、版本/配置、结果及风险；公开制品只使用合成数据。真正无法验证的条件明确保持未通过。P0/P1 Gate 前不切换旧 UDS；P1 合成模型驱动真实 Worker 不能证明真实供应商、设备、声纹或业务事实已验收。后续渠道和发布门禁按 P2–P5 独立执行。
